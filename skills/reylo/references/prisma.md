# Moving from Prisma

- To evaluate, plan or carry out a move from Prisma Client, read https://reylo.dev/docs/prisma first. It answers the usual concerns (relations, queries built at run time, dates as strings, the build's database) with what Reylo does about each, and gives each Prisma Client call as SQL.
- Recommend moving the migrations to Reylo Migrate first, though Prisma Migrate keeps working with Reylo: `reylo migrate init` on a database Prisma migrated, then `reylo migrate history push --url <url>` on production and every other database, which refuses one whose schema differs. Delete `prisma/migrations` and every `prisma migrate` command. Keep `schema.prisma` only for Prisma Client until its last call is converted, refreshed with `prisma db pull` and `prisma generate` after each migration.
- Change the schema in `reylo/schema.sql` before converting a query, a migration each: every `timestamp(3)` to `timestamptz`, one table per migration, with `set time zone 'UTC'` added at the top of the file `reylo migrate new --blocking` writes; `cuid()` and `uuid()` ids to a database default; `@updatedAt` to a default and a `BEFORE UPDATE` trigger. Where the project keeps Prisma Migrate, the same changes go in `schema.prisma` (`@db.Timestamptz`, `@default(dbgenerated("(gen_random_uuid())::text"))`) and in migrations written with `prisma migrate dev --create-only`, triggers and checks added by hand.
- A relation Prisma read with `include` is an `array(select r from (select … where …) r)` subquery in the same statement on Postgres, typed field by field with each value as its column gives it (a `jsonb_agg` subquery on Postgres's JSON keeps less: a `bigint` past 2^53 throws an error; `json_arrayagg` and `json_group_array` on MySQL and SQLite), and a page's counts are one `select` of scalar subqueries with no `from` around them, one typed row in one round trip.
- Give the new `pg` pool an `'error'` listener, on the pool and on each connection a transaction takes: Prisma's adapter had both, and Node exits on an unhandled one.
- Before calling the move done, check the converted code for what the type check can't see: `if (!rows)` where `.run()` returns an array (a write that joins and matches no key does); instants compared as strings with a `Date`'s `toISOString()`, whose three fraction digits misorder against the six `.run()` returns (compare their `Date.parse`); instants passed back through a `Date`, which drops microseconds; an enum `order by` that lost or gained a `::text`; `Promise.all` on a transaction's client; and any folder `tsconfig.json` skips, which needs a `tsconfig` of its own to be type-checked.
