# Running a query: drivers, types and the rest

## Clients and drivers

- Pass the project's own database client to `.run()`: a pool, a client, a transaction or connection taken from one, or a Drizzle connection or Knex instance over one (https://reylo.dev/docs/typescript#run shows each driver's client, https://reylo.dev/docs/typescript#transactions its transaction). At run time Reylo opens no connection of its own.
- Drizzle Postgres, the driver in `drizzle-orm/postgres/client`, is passed as its `Pool` or a `Connection`; its HTTP clients (`neon-http`, `http`, `aurora`) are refused, also under a Drizzle connection or transaction, so on Neon use the `Pool` from `neon-ws`.
- On Postgres, pass the driver's own object, never a hand-written wrapper with a `query()` or `unsafe()` that calls the pool: `.run()` refuses a client that is none of the drivers', since a wrapper returns values the driver already converted. Keep a wrapper a `Pool`, as a subclass or a proxy. A Postgres `date`, `timestamp` or `timestamptz` is read in the ISO style alone, so under another `DateStyle` (set on the session, the role or the database) `.run()` throws: set it to ISO.
- Inside an Effect (Effect 4.1.6 or later), run a query with `effect(query, params)` from `reylo/effect` rather than `.run()`, which refuses an Effect SQL client. It runs on the `SqlClient` the Effect's context provides (`@effect/sql-pg`, `@effect/sql-mysql2`, `@effect/sql-sqlite-node`, `@effect/sql-sqlite-bun`, `@effect/sql-sqlite-do`, `@effect/sql-d1` or `@effect/sql-libsql`), on the transaction's connection inside `sql.withTransaction`, and gives the same values as `.run()`. A database or driver error fails it with Effect's `SqlError`, as Effect's own statements fail; a value Reylo refuses, or a row count the query's cardinality rules out, is a defect (https://reylo.dev/docs/typescript#run has the Effect tab).
- On postgres.js and Bun's `SQL`, Reylo prepares each query as the driver prepares its own; behind a pooler in transaction mode, such as PgBouncer's, create the client with `prepare: false`, which Reylo's queries follow too.
- On MySQL through Cloudflare Hyperdrive, pass a `mysql2` or `mariadb` connection or pool (or Drizzle or Knex over one), made from the binding's `host`, `port`, `user`, `password` and `database`. Hyperdrive refuses prepared statements, so Reylo runs `mysql2` there through `query()`, writing the values into the statement itself: a `FLOAT` column comes back with MySQL's 6 text digits, and an app's `queryFormat` is refused, and so is a value holding a character outside ASCII where the connection or the session reads text in a charset other than UTF-8, as after `SET NAMES`. Postgres through Hyperdrive takes `pg`, postgres.js or Drizzle Postgres as usual (https://reylo.dev/docs/mysql#mysql2).
- On MySQL, `mariadb` 3 runs each query through `execute()`, which binds each value; the driver may send the statement a round trip after `.run()` is called, so await `.run()` before the connection's own `commit()` or `rollback()`. Through Hyperdrive, which refuses prepared statements, and on `mariadb` 2, Reylo runs `query()`, where the driver writes each value into the statement itself. Where such a value holds a quote, a backslash or a character outside ASCII, Reylo first reads the session's `sql_mode` and charset, and `.run()` refuses a value the session would read otherwise: a character outside ASCII where the driver or the session uses a charset other than UTF-8; a double quote or a control character on a session with `NO_BACKSLASH_ESCAPES`, from a `mariadb` older than 3.2.5, 3.3.4, 3.4.7 or 3.5.4 in its line, which writes a backslash before it that the session keeps; a binary value with a quote, a double quote, a backslash or NUL right after a byte of 0x80 or above on a connection whose charset is big5, cp932, gb18030, gbk or sjis, which reads that byte and the driver's backslash as one character, or with a backslash there where the driver writes in one of those charsets and the session reads another; and a quote or a backslash where the session reads a backslash otherwise than the driver writes it, as after a stored routine that sets `sql_mode`, so set it again after calling one (`set session sql_mode = @@session.sql_mode`). The `mariadb` driver and PlanetScale's find a statement's placeholders themselves, as a server without `NO_BACKSLASH_ESCAPES` and `ANSI_QUOTES` reads it, so a statement whose strings those modes read otherwise is refused on them where the server it was typed against has either, and on `mariadb` also where the session has either. Both refuse an array for a parameter, which they would write as a list of values (https://reylo.dev/docs/mysql#mariadb).
- `.runSync()` returns the result itself on a synchronous SQLite client (`better-sqlite3`, `node:sqlite`, `bun:sqlite`, the `Database` of `@tursodatabase/database/compat`, an `oo1` database of `@sqlite.org/sqlite-wasm`, the `Database` of `sql.js` 1.17.0 or later, a Durable Object's `ctx.storage.sql`), so it works inside their synchronous transactions. `.with(client)` binds the query to a client.
- `.readOnly` on a query says Reylo found nothing in it that could write, which a wrapper that retries after a lost connection can test; a write, a locking read and a query that may call a volatile function are `false`, and a user's function counts by its declared volatility.

## Tracing and Standard Query

- To trace or log queries, subscribe to the tracing channel `reylo:query` from `node:diagnostics_channel`, on which Reylo publishes every query it runs; type its events as `QueryTrace` from `reylo`. Each carries the `query` (its `.source` is the file, its `.sql` the statement), `params`, `client`, `sync`, and the `result` or `error`; a `.runSync()` or `.trySync()` call ends on `end`, any other on `asyncEnd` (https://reylo.dev/docs/typescript#observability). Don't wrap the driver or every call for this.
- The result's shape follows the row count Reylo infers: an array, one row, a row or `null`, or nothing for a write without `returning`. On Postgres, a write whose table has a `BEFORE` row trigger is a row or `null` unless every `return` of the trigger's PL/pgSQL returns the row, so look there when a write is unexpectedly nullable. A subquery, a `with` query or a view that selects a table's key unchanged is matched on that key like the table.
- To compare two results of the same Postgres query, as when telling which rows changed, match rows by `query["~standard"].query.key`: the output columns that identify each row of the result, such as `["id"]` for a selected primary key. It is absent for a query of one row at most and where Reylo infers no key (https://reylo.dev/docs/postgres#cardinality). A driver that decodes each value once as it reads it, rather than handing raw rows to `decode`, takes each column's decoder from `query["~standard"].query.columns` (in order, each `{ name, decode }`, typed column by column, never called for NULL) and passes the rows it builds, keyed by the columns' names, to `query["~standard"].query.output(rows)`, which returns what `decode` would. To compare results by position, as a list does, sort by a key of the rows (`order by placed_at desc, id`): the query's `query["~standard"].query.ordered` is then `true`, in its type too, and is absent where rows can tie.

## Value types

- Every driver gives the same types: a 64-bit integer is a `bigint`, a decimal its exact text (a Postgres `money` too, read from the C locale's `$1,234.56`; under another `lc_monetary` a result and a `money` parameter are both refused, so set `lc_monetary = 'C'` or cast through `numeric`, `:fee::numeric`), an instant its ISO 8601 text in UTC with six fraction digits, a pgvector `vector` a `number[]`, an `hstore` an object of its keys, a Postgres row value of a table or composite type and a geometric type (`point` is `{ x, y }`) an object of its fields, a range an object of its bounds (`{ lower: 1, upper: 5, bounds: "[)" }`, `{ empty: true }`) and a multirange an array of them, a MySQL `ENUM` the union of its labels and a `SET` a `Set` of them (which `JSON.stringify` writes as `{}`), and no value is a `Date`; a MySQL `GEOMETRY` is a `Uint8Array`, its WKB after a 4-byte SRID. Pass a parameter in the form `.run()` returns for its type (https://reylo.dev/docs/inference#primitives).
- A JSON parameter is written as `JSON.stringify` writes it, but -0 keeps its sign, and `NaN` or an infinity is rejected before the query runs, since JSON has no number for either (SQLite alone takes an infinity, as `9e999`). MySQL stores neither as a plain parameter either, and SQLite no `NaN`.
- On Postgres, a subquery's row may hold two fields of one name, as `select s from (select 1 as a, 'x' as a) s` does. Then `.run()` returns the last one's value, and the type shows that field (https://reylo.dev/docs/postgres#row-values-and-geometric-types).
- On Postgres, an array column is typed with one dimension, though Postgres lets it hold any number: `.run()` throws an error naming the column on a value of more, whether the array is the column, a row value's field or inside JSON a query builds. Read such a column with `to_jsonb(col)`, typed `Json`, a field with `to_jsonb((col).field)`, or set `allow_nested_arrays: true` in `.reylo.yaml` to type every array column and array parameter at any depth, as `NestedArray<T>`, except an array of JSON (`json[]`, `jsonb[]`), which keeps one dimension since a JSON value may be an array itself (https://reylo.dev/docs/postgres#arrays).

## SQLite and Turso

- On SQLite, a table that is not `STRICT` can hold a value of another kind than its column's declared type, such as the text `'abc'` in an `INTEGER` column; `.run()` throws an error naming the column rather than return it. Replace the value, or read the column with `cast(col as text)`. A `REAL` such as `0.5` in an `INTEGER` column is the exception: `.run()` returns it, and a query's `outputSchema` types that column, and what's computed from it, as a number (https://reylo.dev/docs/sqlite#declared-types-and-strict-tables).
- On SQLite, write a string in single quotes. The type check refuses `select "hello"`, as `better-sqlite3`, `node:sqlite`, libSQL, Turso and SQLite Wasm do, since a double-quoted word is a name (https://reylo.dev/docs/sqlite#limits).
- On Turso Cloud and libSQL, libSQL's vector SQL types: a vector index made with `libsql_vector_idx`, `vector_top_k('<index>', vector32(:q), 5)`, whose `id` is the indexed row's key, and the vector functions, where a vector parameter takes the vector's text (`'[0.1,0.2,0.3]'`) and `vector_distance_cos` is `number | null`. A vector column is a `Uint8Array` from `.run()`; `vector_extract(emb)` returns its text (https://reylo.dev/docs/turso#vectors).
- On Turso Cloud, the functions of the sqlean extensions it loads type too (uuid, crypto, fuzzy, math, stats, text, regexp: `uuid4()`, `levenshtein(a, b)`, `regexp_like(s, re)`, `median(x)`, `generate_series(1, n)`). The SQLite in `@libsql/client` has none of them, so such a query fails on a local `file:` database; the type check lets them through for `@libsql/client` and refuses them for `better-sqlite3` and other SQLite drivers (https://reylo.dev/docs/turso#extensions).

## ClickHouse

- A parameter declares its type, `{id:UInt64}` or `:id::UInt64`, since ClickHouse infers none; a bare `:id` is an error. A parameter can't stand where ClickHouse reads a type from, such as the scale of `toDateTime64` or the type a `CAST` names: write that value in the statement.
- A value a write gives a column with a parameter in it (in `VALUES`, in an `INSERT … SELECT` or in an `UPDATE`'s assignment) needs the column's own type, or one the column holds every value of (a whole number of fewer bits, a `Float32` in a `Float64` column, a `DateTime` in a `DateTime64` column, a type that takes no null in a `Nullable` column, any type in a `Dynamic` column). ClickHouse converts any other in silence (300 into a `UInt8` is 44), so the type check refuses it; to write a value of another type, convert it in the statement, as `{at:String}::DateTime64(3)` does. A sum or a product has a wider type than its operands, and passes where the column keeps each operand's type, as `n = n + {by:UInt32}` on a `UInt32` column does; so does a choice between an enum column's labels, as `if({admin:Bool}, 'admin', 'member')` is.
- ClickHouse enforces no unique key, so a lookup by key returns an array unless it ends in `LIMIT 1`; an aggregate with no `GROUP BY` returns one row. A column is nullable only where its type is `Nullable`: a `LEFT JOIN`'s missing row holds default values, `0` and `''`, unless `join_use_nulls` is set. Set a setting that changes types in the statement's own `SETTINGS` clause or the user's profile, so the type check and the app agree: `.run()` throws when a result's column types are not the ones the type check read.
- Pass `.run()` a client of `@clickhouse/client` or `@clickhouse/client-web`. A `String` or `FixedString` value that is not UTF-8 text throws from `.run()` (select `hex(x)` or `base64Encode(x)`). A `DateTime` is its instant in UTC, a `Map` an array of `{ key, value }` pairs, a named `Tuple` an object, and a `JSON`, `Dynamic` or interval column is an error that says what to select instead (https://reylo.dev/docs/clickhouse).

## Errors, cache and schema drift

- `.run()` throws the driver's own error. `.try()` returns `{ value }`, or `{ error }` for an error the database raised, read into one shape per database whichever driver ran the query: Postgres's `code` and `condition` (`unique_violation`) with the `constraint`, `table` and `column` it names; MySQL's `code` (`ER_DUP_ENTRY`), `errno` and `key`; SQLite's `code` (`SQLITE_CONSTRAINT_UNIQUE`), `table` and `columns`; ClickHouse's `code` (`TOO_MANY_PARTS`) and `number`. The codes are typed, so a misspelled one is a type error, and where the query runs none of the project's own code (a trigger, a function it wrote), each error is narrowed to the constraints, keys and columns of the tables the query writes; any other error, such as a refused connection, still throws. `.trySync()` is the same on a synchronous SQLite client, and each `.sql` module exports the error's type as `QueryError` (https://reylo.dev/docs/typescript#try).
- `reylo/.cache/` is Reylo's cache of each query's analysis. Never edit it or commit it. A type check or a build that can't reach the database reads its types from there and says so, in one `reylo: cannot connect to …; building from reylo/.cache/, analyzed <date>` line per build and in each query's hover: the types are then as old as that date, so start the database and check again before trusting them after a migration.
- A query keeps the types of the schema it was built against: after a migration, a column it names that was retyped or made nullable can return values its types rule out until the next build, and a query the database can no longer run fails with the database's error. An insert of `rows(…)` that leaves a key out writes the column's default as the database had it when the query was built. Build again against the migrated database, and add before you remove (https://reylo.dev/docs/configuration#direct_url).
