<p className="dk-subheader">Reylo Migrate on Render</p>

Run your migrations as your service's pre-deploy command:

```yaml title="render.yaml"
services:
  - type: web
    name: app
    runtime: node
    # ...
    preDeployCommand: npx reylo migrate deploy
```

It runs after the build, on an instance of its own. A migration that fails stops the deploy, and the previous one keeps serving. Pre-deploy commands need a paid instance type.

## Database

Set `DATABASE_URL` from your Render database:

```yaml title="render.yaml"
services:
  - type: web
    name: app
    # ...
    envVars:
      - key: DATABASE_URL
        fromDatabase:
          name: db
          property: connectionString
```

## Builds

A build that type-checks reads your schema before the pre-deploy command migrates it. Give it [a database of its own](/deployment#build-before-migrate).

## Other images

Copy the `reylo` command from Reylo's image, with your `reylo` directory:

```dockerfile title="Dockerfile"
COPY --from=ghcr.io/reylosql/reylo:0.8.3 /usr/local/bin/reylo /usr/local/bin/reylo
COPY reylo/ reylo/
```

Then run it directly:

```yaml title="render.yaml"
services:
  - type: web
    name: app
    runtime: docker
    # ...
    preDeployCommand: reylo migrate deploy
```

Copy `.reylo.yaml` too, if you have one.
