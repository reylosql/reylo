<p className="dk-subheader">Put your schema in a SQL file, and Reylo Migrate writes the migrations</p>

Model your schema in `schema.sql`, write each change into a migration with `reylo migrate new`, and run it with `reylo migrate dev`:

<MigrationsDiagram />

## Basic usage

Install the `reylo` command:

```bash tab="Homebrew"
brew install reylosql/tap/reylo
```

```bash tab="npm"
npm install --global reylo
```

```bash tab="curl"
curl -fsSL https://reylo.dev/install.sh | sh
```

```powershell tab="PowerShell"
irm https://reylo.dev/install.ps1 | iex
```

```bash tab="Scoop"
scoop bucket add reylo https://github.com/reylosql/scoop-bucket
scoop install reylo
```

Start your migrations from your database:

```terminal
$ reylo migrate init
✓ Started reylo/ from postgres://localhost:5432/app
  reylo/
  ├── schema.sql          this database's schema
  ├── migrations/
  │   └── init.sql        the same, recorded as run here
  └── reylo.lock          the order the migrations run in
```

Commit the `reylo` directory to version control (change the path with [`dir`](/docs/configuration#dir) in `.reylo.yaml`).

Edit `schema.sql`:

```sql title="schema.sql"
create table users (
  id integer primary key,
  email text not null -- [!code --]
  email text not null, -- [!code ++]
  bio text -- [!code ++]
);
```

Write the migration:

```terminal
$ reylo migrate new add_bio
✓ Wrote reylo/migrations/20261104140347_add_bio.sql
  + column users.bio text
```

The generated migration is plain SQL. Edit it directly to add data migrations:

```sql title="20261104140347_add_bio.sql"
alter table users add column bio text;
```

Run it on your development database:

```terminal
$ reylo migrate dev
Applying to postgres://localhost:5432/app
  ✓ 20261104140347_add_bio.sql  applied · 4 ms
✓ Wrote reylo/reylo.lock
```

Commit it with the lock, and deploy:

```terminal
$ reylo migrate deploy
Applying to postgres://db.example.com/app
  ✓ 20261104140347_add_bio.sql  applied · 12 ms
✓ Applied 1 migration
```
