Reylo v0.8.2 prints analyses as JSON and TypeScript, adds Rollup and Rolldown entry points, and types MySQL columns through WITH queries.

Three changes can surface in an existing project, listed in [Upgrading from v0.8.1](#upgrading-from-v081).

## JSON and TypeScript from `reylo analyze`

The `reylo analyze` command now prints JSON by default, and TypeScript with `--format typescript` ([#365](https://github.com/reylosql/reylo/pull/365)).

```terminal
$ reylo analyze queries/get_user.sql --format typescript
type Params = { id: number | bigint | string };
type Returns = {
  id: bigint;
  email: string;
  /** Shown on the profile page */
  bio: string | null;
} | null;
```

What it prints:

- **In a terminal:** indented JSON, each object on one line where it fits in 80 columns
- **Piped:** one line of JSON per statement
- **TypeScript:** each statement's `Params` and what `.run()` resolves to, its cardinality applied
- **YAML:** the output v0.8.1 printed, with `--format yaml`
- **One file:** its result alone, with the `file` key only when the command reads several ([#350](https://github.com/reylosql/reylo/pull/350))

## Rollup and Rolldown

Reylo's plugin now has an entry point for each, `reylo/rollup` and `reylo/rolldown` ([#353](https://github.com/reylosql/reylo/pull/353), fixes [#296](https://github.com/reylosql/reylo/issues/296)).

```ts
import { defineConfig } from "rolldown";
import reylo from "reylo/rolldown";

export default defineConfig({
  input: "src/server.ts",
  platform: "node",
  plugins: [reylo()],
});
```

## Replaced columns in migrations

When a migration can't tell renames from new columns, it now lists each column with its own flags ([#324](https://github.com/reylosql/reylo/pull/324)). You can mix renames and drops instead of picking all of one or the other.

```terminal
$ reylo migrate new tidy_columns
✗ This migration can't tell renames from new columns

    posts.title → heading  varchar(100) → varchar(200)
    users.bio   → about    varchar(200) → text

  For each, rename to keep its rows, or drop it:
    --rename posts.title=heading   or   --drop posts.title
    --rename users.bio=about       or   --drop users.bio
  Add the flags you picked to:
    reylo migrate new tidy_columns
```

Replacing a column with a different type kind (such as text to date) now prompts the same way, instead of refusing with a placeholder drop.

## MySQL types through WITH queries

MySQL columns now keep their types through WITH queries, derived tables and UNIONs ([#339](https://github.com/reylosql/reylo/pull/339)).

```sql
with recursive nums (n) as (
  select 1 union all select n + 1 from nums where n < 5
)
select n from nums
```

What it infers:

- **Recursive WITH queries:** columns that no branch makes `NULL` stay non-null, like `n` above (previously every column was nullable)
- **ENUM labels:** `ENUM` columns read through a `WITH` query, derived table or `UNION` keep their literal union, such as `"admin" | "member"` (previously `string`)

## Faster Postgres analysis

Each connection now prepares catalog queries once instead of on every analysis ([#297](https://github.com/reylosql/reylo/pull/297)). Measured across 200 statements against a server 20 ms away:

| Schema size | Before | After | Speedup |
| --- | --- | --- | --- |
| 40 tables | 13.4 s | 9.3 s | **1.4×** |
| 200 tables | 25.1 s | 17.3 s | **1.5×** |

## Upgrading from v0.8.1

Each change below can surface in a project that upgrades from v0.8.1.

### Every dialect

- **The `reylo analyze` command prints JSON by default (previously YAML).** Pass `--format yaml` for scripts reading the old output ([#365](https://github.com/reylosql/reylo/pull/365)).
- **A single-file run of `reylo analyze` omits the `file` key.** Use the path passed on the command line instead ([#350](https://github.com/reylosql/reylo/pull/350)).

### MySQL

- **An `ENUM` column read through a `WITH` query, derived table or `UNION` is now typed as its labels (previously `string`).** Update code that expects a plain `string`. Rows holding MySQL's empty `''` error value also throw in `.run()`, matching plain `ENUM` columns ([#339](https://github.com/reylosql/reylo/pull/339)).
