Reylo imports SQL files into TypeScript, fully typed.

```sql file="schema.sql" tab="Postgres" tab-group="dialect"

create table users (
  id serial primary key,                     -- at most one row per id

  email text unique,                         -- email: string | null
  role user_role not null default 'member',  -- role: "admin" | "member"
  tags text[] not null default '{}',         -- tags: (string | null)[]
  created_at timestamptz                     -- created_at: string
    not null default now()
);

create table posts (
  id serial primary key,
  user_id integer not null references users (id),
  title text not null,
  body text,
  published_at timestamptz
);

create table events (
  id serial primary key,
  kind text not null
    check (kind in ('click', 'key')),        -- kind: "click" | "key"
  payload jsonb not null                     -- payload: what the schema admits

      "type": "object",
      "properties": {
        "x": { "type": "integer" },
        "y": { "type": "integer" },
        "code": { "type": "string" }
      }
    }', payload))
```

Write a query:

```sql title="get_author.sql"
-- hover a table to see its declaration
select u.id, u.name, count(p.id)::int as post_count
from users u
left join posts p on p.user_id = u.id
where u.id = :id::int
group by u.id
```

Import it, and hover over `author` to see its type:

```ts twoslash title="main.ts" dialect="postgres"
// @noErrors
import postgres from "postgres";
import getAuthor from "./get_author.sql";

const db = postgres(process.env.DATABASE_URL);
const author = await getAuthor.run(db, { id: 1 });
```

The types come from your database. Reylo works with Postgres, MySQL and SQLite, and runs each query on the driver you already use.

## Why

TypeScript has had three ways to talk to SQL, each with a cost:

- **ORMs and query builders** like Prisma, Drizzle and Kysely are a second language over SQL. What they can't express becomes a raw query, typed by hand.
- **Raw SQL** needs a row type written by hand, which drifts as the schema changes.
- **Code generators** like sqlc and PgTyped write the types into files. A separate step keeps them current.

Reylo has no generated files. The type check asks the database, and the import is typed.

## How it works

TypeScript 7.1 adds content mappers. A package named in `tsconfig.json` gives the types of a file TypeScript can't read itself:

```jsonc title="tsconfig.json"
{
  "compilerOptions": { /* ... */ },
  "contentMappers": [{ "package": "reylo" }]
}
```

For each `.sql` import, Reylo prepares the statement on your development database, without running it:

<HowItWorksDiagram />

Postgres reports the type of each parameter and each column. For a column read from a table, it also names the table. Reylo then reads the column's `not null` from the catalog.

The database says nothing else about nulls, and nothing about how many rows come back. So Reylo reads the statement with a parser generated from Postgres's own grammar, and works out the rest:

- **Left joins** make the joined table's columns nullable, unless the `where` rules out a null.
- **Expressions** such as `count(…)` are never null, and `coalesce(…)` is non-null when any argument is.
- **Cardinality** comes from the statement's shape. A lookup on a unique key or a `limit 1` returns one row or null.
- **JSON** built with `jsonb_build_object` and `jsonb_agg` is typed field by field.

For JSON, Reylo describes the constructor's arguments as a statement of their own. Each field then carries its column's type and nullability:

<InferenceCard>

```sql file="inferred_user_posts.sql" dialect="postgres"
select u.name,
  jsonb_agg(jsonb_build_object('id', p.id, 'title', p.title)) as posts
from users u
join posts p on p.user_id = u.id
where p.published_at > :since
group by u.id
```

```sql file="inferred_user_posts.sql" dialect="mysql"
select u.name,
  json_arrayagg(json_object('id', p.id, 'title', p.title)) as posts
from users u
join posts p on p.user_id = u.id
where p.published_at > :since
group by u.id
```

```sql file="inferred_user_posts.sql" dialect="sqlite"
select u.name,
  json_group_array(json_object('id', p.id, 'title', p.title)) as posts
from users u
join posts p on p.user_id = u.id
where p.published_at > :since
group by u.id
```

</InferenceCard>

MySQL and SQLite have engines of their own. MySQL's reads the server's prepare metadata, and SQLite's reads the statement as SQLite itself resolves it.

A mistake is a type error, with the database's own message at its line in the `.sql` file:

```sql tab="get_user.sql" dialect="all" errors
select id, nmae, email
from users
where id = :id::int
```

The type check prints it like any other error:

## Limits

- **TypeScript 7.1** is in beta, installed as `typescript@next`.
- **The type check reads your development database.** Each analysis is kept in `reylo/.cache/`, so a check without the database reads the types it last saw.
- **Queries are fixed text.** Reylo doesn't type a query built at run time.

An optional filter is a parameter cast to `nullable(…)`:

<InferenceCard>

```sql file="inferred_posts_by_user.sql" dialect="all"
select id, title
from posts
where user_id = coalesce(:user_id::nullable(int), user_id)
```

</InferenceCard>

A form's filters fit in one [JSON parameter](/inference#dynamic-filtering), checked against its JSON Schema before the query runs.

## Get started

Install Reylo and TypeScript 7.1:

```sh
npm install reylo
npm install -D typescript@next
```

Then add it to `tsconfig.json` and to your runtime, as [the setup](/typescript#setup) shows.

Reylo also writes your migrations, in plain SQL, with [Reylo Migrate](/blog/reylo-migrate). It's MIT licensed, on [GitHub](https://github.com/reylosql/reylo).
