Write a query:

```sql title="get_author.sql"
-- hover a table to see its declaration
select u.id, u.name, count(p.id)::int as post_count
from users u
left join posts p on p.user_id = u.id
where u.id = :id::int
group by u.id
```

Import it, and hover over `author` to see its type:

```ts twoslash title="main.ts" dialect="postgres"
// @noErrors
import postgres from "postgres";
import getAuthor from "./get_author.sql";

const db = postgres(process.env.DATABASE_URL);
const author = await getAuthor.run(db, { id: 1 });
```

There's no codegen step and no generated file. The types come straight from your database. The query runs on the driver you already use, on Postgres, MySQL or SQLite.

## Why Reylo

There have been three ways to query a database from TypeScript, and each falls short:

- **ORMs and query builders** — Prisma, Drizzle and Kysely build your SQL from TypeScript. But they're a second language over SQL. Whatever they can't express falls back to a raw query you type by hand.
- **Raw SQL** — You write the SQL yourself, and declare each query's row type by hand. Nothing checks that type against the database, so it drifts as the schema changes.
- **Code generators** — sqlc and PgTyped read your queries and generate typed functions. But that's a build step to run after every change, and generated code to commit and keep in sync.

Reylo keeps the SQL and drops the rest. You write plain SQL, and TypeScript gets its types from the database itself.

## How it works

TypeScript 7.1 adds the content mapper API, adding support for external file types. It lets you dynamically generate a static type signature for an import of a file with a given extension. Reylo is a content mapper for `.sql`:

```jsonc title="tsconfig.json"
{
  "compilerOptions": { /* ... */ },
  "contentMappers": [{ "package": "reylo" }]
}
```

When TypeScript meets a `.sql` import, Reylo sends the query to your live development database. The database compiles it without running it, and hands back the types of its parameters and columns. Reylo reads your schema information too: the catalog on Postgres, and the information tables on MySQL and SQLite.

## Get started

Install Reylo and TypeScript 7.1:

```sh
npm install reylo
npm install -D typescript@next
```

Then add the `tsconfig.json` entry above, and Reylo's plugin for your runtime or bundler, as [the setup](/typescript#setup) shows.

Reylo also writes your migrations, in plain SQL, with [Reylo Migrate](/blog/reylo-migrate). It's MIT licensed, on [GitHub](https://github.com/reylosql/reylo).
