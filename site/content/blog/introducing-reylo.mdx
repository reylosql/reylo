Reylo lets you import SQL files directly into TypeScript with full type safety. If you have a query like this:

```sql title="get_author.sql"
-- hover a table to see its declaration
select u.id, u.name, count(p.id)::int as post_count
from users u
left join posts p on p.user_id = u.id
where u.id = :id::int
group by u.id
```

You can import it straight into TypeScript. Hover over `author` to see the type Reylo infers for it:

```ts twoslash title="main.ts" dialect="postgres"
// @noErrors
import postgres from "postgres";
import getAuthor from "./get_author.sql";

const db = postgres(process.env.DATABASE_URL);
const author = await getAuthor.run(db, { id: 1 });
```

There's no codegen step and no generated file: the types come straight from your database. The query runs on whatever driver you already use, on Postgres, MySQL or SQLite.

## How it works

TypeScript 7.1 adds the content mapper API, adding support for external file types. It lets you dynamically generate a static type signature for an import of a file with a given extension. Reylo is a content mapper for `.sql`:

```jsonc title="tsconfig.json"
{
  "compilerOptions": { /* ... */ },
  "contentMappers": [{ "package": "reylo" }]
}
```

When TypeScript meets a `.sql` import, Reylo sends the query to your live development database. The database compiles it without running it, and hands back the types of its parameters and columns. Reylo reads your schema information too: the catalog on Postgres, and the information tables on MySQL and SQLite.

## Get started

To use it in your own project, install Reylo along with TypeScript 7.1:

```sh
npm install reylo
npm install -D typescript@next
```

Then you add the `tsconfig.json` entry from above, plus Reylo's plugin for your runtime or bundler. [The setup guide](/typescript#setup) walks through each one.
