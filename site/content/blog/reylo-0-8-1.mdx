Reylo v0.8.1 adds Turso Cloud sqlean functions, Drizzle's Postgres driver, MySQL migration grants, and faster remote Postgres analysis.

Three changes can surface in an existing project, listed in [Upgrading from v0.8.0](#upgrading-from-v080).

## Turso Cloud's sqlean functions

The type check now recognizes the sqlean extension functions Turso Cloud loads, instead of refusing them with `no such function` ([#327](https://github.com/reylosql/reylo/pull/327)).

```sql
select id, name, levenshtein(name, :name) as distance
from users
where regexp_like(name, '^[A-Z]')
order by distance
limit 5
```

The functions it types, by extension:

- **uuid:** `uuid4`, `uuid7`, `gen_random_uuid`, `uuid_str`, `uuid_blob`
- **crypto:** `md5`, `sha1`, `sha256`, `sha384`, `sha512`, `blake3`, `encode`, `decode`
- **fuzzy:** `levenshtein`, `dlevenshtein`, `edit_distance`, `hamming`, `jaro_winkler`, `caverphone`, `translit`
- **stats:** `median`, `percentile`, `percentile_90`, `stddev`, `variance`, `var_samp`
- **text:** `left`, `right`, `lpad`, `rpad`, `repeat`, `reverse`, `split_part`, `starts_with`
- **regexp:** `regexp_like`, `regexp_substr`, `regexp_capture`, `regexp_replace`
- **series:** `generate_series` and `stats_seq`

The SQLite inside `@libsql/client` has none of them, so a query that calls one fails on a local `file:` database.

## Drizzle's Postgres driver

Queries now run on the Postgres driver `drizzle-orm` ships from 1.0.0-rc.6 ([#338](https://github.com/reylosql/reylo/pull/338)).

```ts
import { Pool } from "drizzle-orm/postgres/client";
import getUser from "./get_user.sql";

const db = new Pool({ url: process.env.DATABASE_URL });
const user = await getUser.run(db, { id: 1 });
```

What it runs on:

- **Clients:** its `Pool`, a connection, a transaction or savepoint, and a `drizzle()` connection over any of them
- **Neon:** `drizzle-orm/postgres/client/neon-ws`, over a WebSocket
- **Refused:** the `neon-http`, `http` and `aurora` clients, whose results don't name each column's type

## MySQL grants in migrations

Migrations now read, compare and plan MySQL grants ([#328](https://github.com/reylosql/reylo/pull/328)).

```diff
-grant select on users to 'reader'@'%';
+grant select, insert on users to 'reader'@'%' with grant option;
+grant update (full_name, code) on users to 'app_role';
```

The migration planned for that change:

```sql
grant update (code), update (full_name) on users to `app_role`@`%`;
grant insert on users to `reader`@`%` with grant option;
```

What it covers:

- **Objects:** grants on tables, views, columns and routines, with or without `with grant option`
- **Drops and renames:** grants are revoked before an object is dropped or renamed, then re-granted afterward, since MySQL keeps stale grants
- **Introspection:** `reylo db introspect` and `reylo migrate init` write grants into `schema.sql`
- **Refused:** server-wide, cross-database, role and proxy grants, plus `set password` and `set default role`
- **Permissions:** accounts without read access to MySQL's privilege tables get an error listing the grant statements needed

## Faster Postgres analysis

Each round of Postgres analysis now pipelines its queries instead of waiting for each one in sequence ([#335](https://github.com/reylosql/reylo/pull/335)). Measured across 2,320 statements against a server ~100 ms away:

| Metric | Before | After | Speedup |
| --- | --- | --- | --- |
| Median | 514 ms | 242 ms | **2.1×** |
| p90 | 2.7 s | 0.9 s | **3.0×** |
| Slowest | 18.5 s | 2.7 s | **6.9×** |

## Upgrading from v0.8.0

Each change below can surface in a project that upgrades from v0.8.0.

### Postgres

- **The type check refuses Supabase's transaction pooler on port 6543.** Point the type check at the session pooler named in the error ([#334](https://github.com/reylosql/reylo/pull/334)).

### MySQL

- **A `BIT` computed with `coalesce`, `ifnull`, `greatest`, `least` or `any_value` inside a view, derived table or `WITH` query is now `unknown` (previously bytes).** MySQL returns decimal digits rather than bytes there; narrow the `unknown` value where the type check asks ([#329](https://github.com/reylosql/reylo/pull/329)).

### SQLite

- **Calling `soundex(x)` on a nullable `x` now returns `string | null` (previously `string`).** Handle `null`, which Turso Cloud's `soundex` returns for `NULL` ([#327](https://github.com/reylosql/reylo/pull/327)).
