Reylo v0.8.3 initializes Reylo Migrate on Postgres without `pg_dump`, adds recovery steps to failed deploys, prints query rows from `reylo run`, and flags missing required columns on SQLite.

A few changes can surface in an existing project, listed in [Upgrading from v0.8.2](#upgrading-from-v082).

## Reylo Migrate

A migration that fails on deploy now prints the exact recovery steps ([#389](https://github.com/reylosql/reylo/pull/389)).

```terminal
Applying to postgres://localhost:57432/pinboard_prod
  ✗ 20261122183737_handle_len_unique.sql  failed

✗ The migration 20261122183737_handle_len_unique.sql failed and was rolled back
  could not create unique index "users_handle_len" (Key (length(handle::text))=(1) is duplicated.)
  Nothing was recorded, so the next deploy runs it again.

  Fix the file, lock the fix and deploy again:
    reylo migrate dev
    reylo migrate deploy
  If another database already ran it, write a new migration instead:
    reylo migrate new <name>
```

What else changed:

- **Existing databases:** `reylo migrate init` and `reylo db introspect` now emit Reylo's own SQL across every schema in Postgres. They no longer require a matching `pg_dump` binary ([#390](https://github.com/reylosql/reylo/pull/390)).
- **Concurrent deploys:** parallel deploys no longer deadlock on a pending `create index concurrently` ([#386](https://github.com/reylosql/reylo/pull/386)).
- **Summaries:** `reylo migrate new` summarizes each change cleanly (new tables as one line with their columns below), and schema diffs label both sides ([#383](https://github.com/reylosql/reylo/pull/383), [#424](https://github.com/reylosql/reylo/pull/424)).
- **After a push:** `reylo migrate dev` now reports that the schema is ahead of migrations after `reylo db push`, instead of reporting a mismatch ([#388](https://github.com/reylosql/reylo/pull/388)).
- **CI detection:** `CI=false`, `CI=0` and an empty `CI` no longer count as CI ([#388](https://github.com/reylosql/reylo/pull/388)).
- **Enum values:** adding a Postgres enum value emits `alter type … add value` alone instead of rebuilding dependent views, policies and triggers. Adding and using a value in one edit splits into two migrations ([#400](https://github.com/reylosql/reylo/pull/400)).
- **Column defaults:** changing a column's default, `not null` constraint or identity no longer rebuilds dependent views, policies and triggers ([#400](https://github.com/reylosql/reylo/pull/400)).
- **Renames:** ambiguous column renames render as a diff with a command for each option, and generated renames print as a single `~` line ([#419](https://github.com/reylosql/reylo/pull/419)).
- **Extensions:** `reylo migrate new` captures extensions added directly on the dev database and excludes extension-owned types and rules from `schema.sql` ([#421](https://github.com/reylosql/reylo/pull/421), [#422](https://github.com/reylosql/reylo/pull/422)).
- **Manual changes:** `reylo migrate history push` records manual changes even when their migration sorts behind an unapplied one, reordering it in the lockfile ([#387](https://github.com/reylosql/reylo/pull/387)).
- **Lockfile format:** `reylo.lock` now carries `version: 1` with structured `{ name, checksum }` entries. Locks written by a newer Reylo fail with an upgrade prompt ([#425](https://github.com/reylosql/reylo/pull/425)).

## Rows from `reylo run`

The `reylo run` command now prints up to 50 returned rows in a formatted table ([#389](https://github.com/reylosql/reylo/pull/389)).

```terminal
$ reylo run 'select id, email, bio from users'
✓ select id, email, bio from users
  id  email              bio
  ──  ─────────────────  ───────────────────────
   1  ada@example.com    Wrote the first program
   2  grace@example.com  null
  Returned 2 rows
```

## Required columns on SQLite

The type check now refuses SQLite inserts that omit a `NOT NULL` column with no default ([#381](https://github.com/reylosql/reylo/pull/381)).

```sql
insert into req (id, name) values (:id, :name)
--          ^^^ Column "email" of "req" is NOT NULL with no default, and this insert leaves it out,
--              so SQLite refuses every row it inserts.
```

The check stands down when SQLite can skip or fill the row: `OR IGNORE`, an `ON CONFLICT IGNORE` constraint, or a `BEFORE` / `INSTEAD OF` insert trigger.

## Postgres types

Postgres now infers non-null types for more built-in functions ([#382](https://github.com/reylosql/reylo/pull/382), [#384](https://github.com/reylosql/reylo/pull/384)).

```sql
select t.id, array_agg(jsonb_build_object('email', m.email)) as objects, array_agg(now()) as times
from teams t join members m on m.team_id = t.id
group by t.id
```

What it infers:

- **Never-null built-ins:** elements of `objects` and `times` above are now non-null, along with `array_agg` over `concat`, `gen_random_uuid()` and other never-null built-ins
- **Aggregates with custom casts:** expressions like `round(coalesce(sum(x), 0), 2)` stay non-null even when an extension such as pgvector adds an implicit cast (regression from v0.8.0)

## MySQL statements

The MySQL engine now parses queries with Reylo's own grammar, covering more of MySQL 8.4 ([#380](https://github.com/reylosql/reylo/pull/380)).

```sql
table tags limit 1
```

What it reads:

- **`TABLE` statements:** typed from the table itself, so `table tags limit 1` returns at most one row of non-null columns (previously many rows of nullable ones)
- **More syntax:** derived-table column aliases, multiple locking clauses, `CAST … AT TIME ZONE`, `GROUP BY ROLLUP(…)`, `JSON_VALUE … RETURNING` and `NATURAL INNER JOIN`
- **Accurate parsing:** `UPDATE IGNORE`, `DELETE LOW_PRIORITY`, `BINARY a = b`, bit literals like `0b1011`, and the precedence of `^` and shift operators

## Upgrading from v0.8.2

Each change below can surface in a project that upgrades from v0.8.2.

### Every dialect

- **The `reylo.lock` format now uses `version: 1` and `{ name, checksum }` entries.** Existing v0.8.2 lockfiles still read, and the next `reylo migrate dev` or `reylo migrate lock` rewrites them. Older v0.8.2 binaries refuse the new format, so upgrade every copy of Reylo together ([#425](https://github.com/reylosql/reylo/pull/425)).

### Postgres

- **Data-modifying `WITH` inserts that omit a required column are now refused**, matching plain inserts. Provide the column or add a default ([#381](https://github.com/reylosql/reylo/pull/381)).
- **Arrays of `ROLLUP` keys or subquery grouping sets now have nullable elements (previously non-null).** Handle `null` elements where the type check asks ([#382](https://github.com/reylosql/reylo/pull/382)).

### SQLite

- **Inserts omitting a `NOT NULL` column with no default now fail with `reylo16`.** Provide the column or add a default ([#381](https://github.com/reylosql/reylo/pull/381)).
- **Virtual table columns are now nullable**, since SQLite does not enforce `NOT NULL` constraints declared by virtual table modules. Handle `null` where the type check asks ([#381](https://github.com/reylosql/reylo/pull/381)).
